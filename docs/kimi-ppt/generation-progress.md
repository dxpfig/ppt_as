# 生成过程与失败恢复

主工作区的“创作过程”面板展示公开的执行状态：读取材料、内容策划、准备素材、逐页创作、检查修复、渲染导出和完成交付。点击阶段可查看逐页状态、重试次数及最近事件；详情区限制高度，完成后自动收起，失败时保留恢复入口。旧任务缺少事件的阶段显示未知，不补造历史。

单独导出任务默认只显示渲染导出与完成交付；如实际记录了检查修复或其他阶段的失败/取消，会保留相应节点，不将未执行的创作阶段标为完成。

这些内容来自真实任务事件，不包含模型内部思维链、原始回答或完整提示词。计时显示耗时和最近状态更新时间，不据此推算完成百分比。已保存页数表示检查点中的页面数量，不表示最终文件已通过导出验收。

后端 `generate_pptd(..., on_event=...)` 发送阶段与页面的 `started/completed/retrying/waiting/failed` 事件；`job_execution.py` 维护 `job.execution`，经现有 SSE 和轮询通道交付。页面仅在结构检查通过且检查点保存后标为已保存。所有页保存后仍需渲染、字体与原生文件检查。

失败响应包含简短说明和 `diagnostic`：错误类别、发生阶段、已知页面位置；排版或格式问题使用独立的 `issues` 列表。模型超时、连接、认证和限流错误不再混称为渲染失败。真实错误类型保留在诊断中，密钥和原始供应商响应不展示。

PPTD 请求新增 `outputMode: auto | adaptive | direct`，默认 auto。仅已确认的官方 MiniMax-M3 接口在 auto 下使用直接 JSON 输出及流式接收，以避免思考耗尽整个输出预算；adaptive 可保留该模型的自适应思考。其他模型沿用供应商默认方式，direct 对未验证接口会明确拒绝。规则原文、16000 token 输出限制、严格 JSON 和结构校验均保留。执行模式变化不改变内容标识，因此旧检查点可继续使用。

恢复任务沿用已保存页面，模型只生成缺页或修复有明确问题的页。停止、重启或失败保留检查点；观察页面不会自动重试。只有全量检查通过才发布 PPTX、PDF、源文件和最终预览。

浏览器排版检查与原生 PPTX 兼容检查会汇总同一轮的可定位问题，再交给模型修复，避免字体、排版及原生格式问题分别消耗有限的修复轮次。字体覆盖问题定位到真正使用该字体的页面与元素。导出报告确认的是受支持能力、字体、文本溢出、画布边界及内容存在；当前不检测不同元素之间的文字重叠，仍需视觉验收。

验证入口：`pnpm test:studio`、`pnpm test:pptd`，以及 `frontend/src/pages/studio/` 下的状态与浏览器测试。真实模型运行和导出验收使用用户项目的恢复任务，隔离的浏览器测试不会触发模型调用。
