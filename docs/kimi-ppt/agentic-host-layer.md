# Kimi 专家（agentic）路线的宿主层与交付门禁

日期：2026-10-14。适用对象：勾选“Kimi 专家（agentic，1:1 复刻）”后生成的任务。模型在
`deck/` 里自由写页，宿主随后把公司模板叠加上去，并在交付前渲染最终稿做真排版检查。

## 宿主在模型产物之上做了什么

`agent_service/kimi_agent.py` 的 `_apply_host_transforms` 是唯一入口，顺序固定：

1. **封面/致谢复用模板**：把模型首页的标题、副标题与日期写进模板封面自己的文本槽，
   末页写进模板致谢页。槽位按字号排序，日期取自含年份且以年份开头的那行；小槽放不下
   整句时留空，不硬塞。
2. **正文背景取自模板**：统计模板正文页里覆盖整页的背景图（出现次数最多的一张，即
   “一张版面大小的图片”），并删掉模型自造的整宽底部装饰带（`shapeName: custom` 的全宽贴底
   形状）。页面上已有的背景层——页级 `background` 或覆盖整页的图片元素——若不是这张图，
   直接改指向模板这张图，而不是再叠一层：模板正文共用一张背景，混入第二种更浓的变体会让
   目录页看起来不配套。字节相同的图片会复用，不重复拷文件。
3. **表格字体**：表格样式没声明 `fontFamily` 时补上文档正文的字体。渲染器对没有字体的
   单元格回落到内置默认字体，表格会与同页其他文字字体不同；模板自带的表格本来就逐格写死字体。
4. **角标元素**：右上图形、右下 logo 与公司名按模板原样叠加到正文页；封面与致谢页不叠加。
5. **角标避让**：叠加前先把我们自己的元素移出角标区域——宽度收窄到角标左侧，或整体左移/
   上下让位。整页背景与角标本身不参与避让。
6. **角标文本框**：模板自带的公司名文本框高度小于自身字号时按字号撑高，避免渲染溢出。

## 交付门禁

模型自己跑 `kimi_slides screenshot` 时看不到封面/致谢的最终形态（宿主是之后才替换的），
所以宿主在提交前再跑一次真实渲染检查（`final_layout_issues`）：

- **浏览器排版检查**：复用 `pptd_engine/web/export_pdf.cjs`，报告文字溢出、文字重叠、
  超出画布、内容缺失、未支持元素与字体问题；问题按页面与元素定位。
- **可读性检查**：渲染 PNG，把每个文本框切成 3×3 块，用每块的主色与文字颜色算 WCAG
  对比度，最低一块低于 2.0:1 即判为不可读（未声明字色按渲染器默认黑色参与计算）。
- **AI 视觉审稿**：把渲染图拼成总览图交给配置的视觉模型（`PPT_VISION_*`），按原文设计规则
  看整体风格、排版节奏、字体与字号一致性、多余装饰和文字拥挤。默认开启，`PPT_KIMI_VISUAL_REVIEW=0`
  关闭；视觉模型不可用时只记录说明，不阻断交付。
- 两类问题合成一轮反馈交回模型修复（`PPT_KIMI_REPAIR_ROUNDS`，默认 1 轮），仍不通过则
  任务失败并带定位信息。字体族未解析（模板本身要求微软雅黑/思源黑体）只作提示，不阻断。

门禁分工需要如实记录：几何与可读性问题（溢出、重叠、超出色块、对比度过低）靠确定性检查，
可复现且必须清零；“并列项之间加装饰分隔线”“表格与正文字体/字号不一致”这类审美问题只有
视觉模型能判断。实测同一份稿子，视觉模型一次报出 2 条问题、一次返回通过，所以它作为补充
证据，不能单独当作发布条件。

修复轮（`PPT_KIMI_REPAIR_ROUNDS`，默认 2 轮）用完后仍有问题，不再让整个任务失败：文档照常
提交为可编辑稿，未通过项按页面和元素列在回复里，任务摘要写明"几项排版问题待确认"，
进度面板保留一条未通过的检查节点。硬失败会把一份 95% 可用的稿子变成"什么都没有"，
用户既看不到内容也拿不到可以修改的东西。

## 默认生成方式：原生 Kimi 工作流

`kimi-slides` 默认恢复为完整的 Kimi 工具驱动工作流，因为长文档演示的质量主要来自读取原始
资料、分析模板截图、规划叙事、自由编写页面和截图复盘，而不是把预测好的角色提示词逐页转换成
JSON。宿主协调的逐页管线仍可用 `PPT_KIMI_AGENTIC=0` 显式启用，但不再默认使用。

长资料不再整份塞进首条消息。服务端会：

1. 把原始文件复制进 agent 工作区的 `sources/`。
2. 对 DOCX 使用 WordprocessingML 结构解析，保留标题层级、列表和表格，生成
   `sources/reference.md` 与 `sources/reference-outline.md`。
3. 在首条消息中只提供文件路径、结构提纲和字数；agent 先读提纲，再按需用 Read/Grep/Bash
   读取原文相关章节。
4. 原始文件始终保留在 `sources/`，结构化 Markdown 有损失时以原文件为准。

通用长文档规则同时要求：目录必须对应真实章节，完整报告不能被压成少量摘要页，每个页面只承担
一个主判断，并根据内容选择矩阵、时间轴、流程、表格或并列卡片，避免整稿重复同一种版式。

| 右下角章节信息与公司名重叠                   | 模型把章节导航放在右下角，宿主又按模板叠加了公司角标                                                                                                            | `_clear_corner_conflicts` 就地避让                                                                                      |

| “视觉检视”没发现上述问题                     | ① 字体未解析时 `export_pdf.cjs` 直接 `reject` 返回，后面的排版检查根本没跑；② 模型自查发生在宿主替换封面/致谢之前；③ 浏览器空段落高度为 0，与 PowerPoint 不一致 | `export_pdf.cjs` 改为收集字体问题后继续检查；`run_kimi` 增加最终门禁；`pptd_engine/web/index.html` 给空段落补空文本节点 |
| 正文/目录背景仍不是模板那张图                | 宿主只处理“完全没有背景”的页面，页面上已有第二张背景图时直接跳过，也从未覆盖页级 `background`                                                                   | `_apply_background` 改为按模板那张图重指背景层                                                                          |
| 表格字体与正文不一致                         | 表格样式没有 `fontFamily`，渲染器回落到内置字体                                                                                                                 | `_normalize_table_fonts` 继承文档正文字体                                                                               |
| 并列项之间的装饰分隔线、正文与表格字号不一致 | 纯审美判断，几何检查看不到；agentic 路线此前根本没有视觉审稿                                                                                                    | 提示词新增两条设计约束；`review_deck_overview` + `visual_overview_issues` 接入 AI 视觉审稿                              |

## 复现与验证

```bash
pnpm test:pptd      # 57 项 JS/Chromium + 74 项 Python 引擎测试
pnpm test:studio    # 242 项，含 Kimi 宿主层与端到端门禁
```

离线复核（不调用模型）可对已有工作区重跑宿主层：读取 `deck/` 与 `template-pptd/`，
执行 `_apply_host_transforms`、`_write_deck`、`final_layout_issues`，再人工看图确认。

## 已知边界

- 整页背景只支持图片资源；模板若用纯色/渐变背景形状，当前不复制。
- 避让策略是“收窄宽度 → 左移 → 上下让位”的确定性规则，复杂版式仍需视觉复核。
- 可读性阈值是粗筛，用于挡“几乎看不清”的文字，不等同完整 WCAG 审计。
- AI 视觉审稿依赖所配置视觉模型的能力与稳定性，结论会波动；确定性问题仍以浏览器检查为准。
- 字体族未解析仍会让浏览器使用回退字体，与 PowerPoint 实机排版可能不同。
