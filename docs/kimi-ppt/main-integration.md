## 当前主链路

主应用地址为 `http://192.168.0.10:5174/`，Python 服务监听本机 8001，BFF 为 3002。8765 属于另一项目，未修改。独立实验工作台不再是主要交付入口。

AgentScope 直接生成 PPTD v2 主文档和 `.page` 对象，保留七类元素及自由坐标。模型分阶段获得原始主流程、格式、字体、形状、场景索引，以及选择场景的完整原文。页面数量遵循用户指定与材料需要；默认不强制六页或八页，不再经过旧标题/要点模型。

新任务经历：上下文与真实研究 → 叙事规划 → 并发逐页设计 → 结构校验与修复 → 浏览器实际排版检查 → 原生 PPTX 检查 → 发布 PPTX、PDF、PNG、PPTD 源文件包及报告。浏览器或导出器发现字体、内容溢出、裁切、元素缺失或不支持的样式时，会向生成器提供具体页面/元素问题；未通过检查的内容不会标记交付完成。

## 文档与任务一致性

- `runtime/studio/documents/{id}/document.pptd` 是稳定的源入口，指向不可变版本目录；版本元数据在源包之外。
- 编辑、恢复和模板导入使用 `expectedRevision` 检查。旧项目 JSON、过期 autosave、失败任务均不能替换新的文档内容。
- 导出先锁定同一文档快照，再生成所有文件。源版本与产物版本不同则阻止发布。
- 任务保存请求、检查点、事件、trace ID。主界面使用 SSE，连接失败时切换轮询。重启后标记中断，不自动重复模型调用。
- “继续检查点”和“重新尝试”创建新的任务记录并保留失败记录；中断后文档已变化则拒绝使用旧检查点。
- AI 完成内容但导出失败时保留可编辑源文档。只有当前版本通过导出检查才显示可交付状态。

## 主界面

使用正式 PPTD 工作台预览和元素编辑；预览与编辑模式分离，嵌入画布按容器宽度缩放。支持选择页面后局部 AI 修改、版本恢复、源 ZIP、PPTX 与 PDF 下载。

输入支持文本资料、显式网页/PDF 链接、视觉参考图片、完整设计规范，以及已有 PPTX/POTX 模板的实际导入。图片参考以多模态字节送入支持该能力的配置模型，不能把链接字符串等同于已看过图片。旧项目保留明确迁移入口，迁移会复制已缓存图片并保留讲稿。

## 已知边界

- 未获得 Kimi 私有引擎或 App 源码；实现的是已归档规则、公开格式与本地对应能力。
- 任意 Office 模板的母版继承、主题色、效果、动画导入仍不完整，导入会保留原件及损失报告；丢失对象时拒绝覆盖当前演示。
- 原生导出仍有部分文本/填充样式限制；新内容用等价可编辑元素表达，检测到静默丢失时阻止交付。原生 Office 不对应的图表使用允许的可编辑矢量实现并保留数据。
- 主 UI 的直接元素编辑目前提供文字与坐标/尺寸；完整源字段保持在 PPTD 中，不代表所有高级字段已有可视化控件。
- 未配置 Tavily、Serper 或 SearxNG 文本检索时明确记录不可用；用户明确给出的公开链接仍会读取。扫描 PDF 需 OCR，此轮不宣称已有 OCR。
- Microsoft PowerPoint 桌面软件中的字体与动画效果仍需人工兼容验收；当前自动验收为浏览器、PDF 和 OOXML。
