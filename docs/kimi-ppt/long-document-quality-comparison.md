## 结论

最终视觉对照结果为原生 `95`、当前 `90`，AI 审稿判定“高度一致、可用于验收”。
两版在模板一致性、五章叙事骨架、关键内容模块、数据表格、章节节奏和正式收束上均已对齐。
当前版比原生多 6 页，部分页面留白和字号权重仍有轻微差异，但没有关键质量缺口。

## 之前质量退化的根因

1. 默认路线从原生 Kimi 工具驱动工作流，切换成了通用的逐页 JSON 生成器。
   后者保留了 Kimi 规则文本，却失去了读取模板截图、自由编排页面、截图复盘和
   根据实际视觉效果继续修改的能力。
2. 原生版 18 页；退化版只有 13 页，把多个一级章节压进了少量摘要页，目录、章节
   过渡和正式收尾也被压缩。
3. 浏览器端 Mammoth `extractRawText` 丢失了 DOCX 的标题层级和表格关系。
   原始 DOCX 实际包含 5 个一级标题、23 个二级标题、41 个三级标题和 6 张表。
4. 整份长资料和后续页面会话放在同一个长 ReAct loop 内，容易触发上下文压缩、
   模型超时和单 Agent 迭代上限。

## 当前实现

### 原生 Kimi 工作流为默认

`PPT_KIMI_AGENTIC` 默认启用完整工具驱动流程。逐页协调管线仍保留在
`PPT_KIMI_AGENTIC=0`，但不作为质量优先的默认路径。

### 通用长文档规则

宿主提示层新增的是与具体主题无关的规则：

- 完整报告必须保留封面、与正文对应的目录、论证推进和正式收尾。
- 长结构化报告通常使用 14–20 页的有效内容范围；用户指定页数时以用户为准。
- 不把多个主要章节压成一张泛化摘要页，也不为每一章机械增加空白扉页。
- 每页只承担一个主判断，正文、证据和行动之间要有明确关系。
- 根据内容选择矩阵、时间线、流程、表格或并列卡片，不连续重复同一种布局。
- 保留原文中能支撑结论的实体、日期、指标、比较关系和数据表。

### DOCX 结构读取

生成前，宿主会把原始文件复制到 agent 工作区，并生成：

- `sources/original.docx`：原始文件，权威来源。
- `sources/reference.md`：保留标题层级、列表和表格的结构化 Markdown。
- `sources/reference-outline.md`：章节提纲。

agent 先读取提纲，再按需读取原文；结构转换有损失时以原始 DOCX 为准。
这比只把 Mammoth 的纯文本塞给模型更完整，也不需要假设聊天模型可以直接理解二进制
DOCX。

### 长稿分段续写

长稿不再由单个 Agent 一次写完全部页面：

1. 首批创建 `deck.pptd`、`deck/plan.json` 和最多 5 页。
2. 后续批次使用全新的 Agent 上下文，每批只补 2 页。
3. 每批读取现有计划、代表页和章节提纲，不重读全部模板截图或整份资料。
4. 批次失败后，下一任务从已有工作区复制未完成 deck，只继续缺页。
5. 宿主总时限提高到 90 分钟，避免长稿在最终审稿前被旧的 30 分钟上限取消。
