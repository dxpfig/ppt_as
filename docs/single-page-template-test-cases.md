# 用户模板单页生成基准用例（评审稿）

状态：已批准，自 2026-10-23 起作为页面生成链路的强制回归基准。机器可读用例清单位于 `benchmarks/single-page-template/cases.v1.json`。

## 1. 固定测试环境

| 项目         | 固定值                                                                    |
| ------------ | ------------------------------------------------------------------------- |
| 用户模板     | `d962b90ffef240d0be9dde7fee39750b`                                        |
| 模板文件     | `runtime/studio/templates/d962b90ffef240d0be9dde7fee39750b/template.pptx` |
| 模板 SHA-256 | `e197ff456d0678dd15d022eee1814869db469965606422b02c5d96397b792113`        |
| 模板页数     | 19                                                                        |
| 画布         | 960 × 540                                                                 |
| 主要字体     | 微软雅黑、MiSans、Arial、思源黑体、Noto Sans SC                           |
| 生成任务     | `kimi-slides`，固定 `pageCount=1`                                         |
| 图像来源     | `none`，避免图片检索成为变量                                              |
| 研究         | 关闭                                                                      |
| 场景         | `management-report`                                                       |
| 输出         | 单页 PPTD、单页预览 PNG、性能 JSON、结构化问题清单                        |

模板中与本测试直接相关的页面：

- `template-page-01`：封面，图片 2、文本 3、形状 1，标题约 66pt。
- `template-page-02`：目录，图片 2、文本 9、圆角矩形 8，标题约 40pt。
- `template-page-19`：结束页，图片 2、文本 2，主张文字约 100pt。
- 正文页共享模板背景、页脚公司名及右上角装饰。

## 2. 测试隔离和统一流程

每个用例使用独立临时项目和工作区，不修改用户现有项目或模板文件。

统一流程：

1. 加载并分析用户模板。
2. 使用固定的一页测试计划，避免规划阶段自行扩张页数。
3. 生成单页 JSON 布局。
4. 宿主应用对应模板角色：封面、正文、目录或结束页。
5. 编译 PPTD。
6. 执行结构校验。
7. 执行 Chromium 渲染与几何测量。
8. 执行 AI 单页视觉检视。
9. 如未通过，执行单页修复并重新走第 6–8 步，最多 3 轮。
10. 输出首轮问题、每轮修复问题、最终状态和完整性能数据。

每个用例必须同时记录：

- 不经修复首轮是否通过。
- 首轮问题类型和数量。
- 修复轮数和最终是否通过。
- 各阶段耗时。
- 生成产物和预览图。

### 元素统计口径

本文的“页面元素”指最终编译进 `.page`、能够被单独选择或在浏览器中形成实际 DOM 节点的可见元素，不按模型 JSON 的语义节点计数。

计数规则：

- 文本块：每个独立 PPTD `text` 元素计 1；换行、段落和富文本片段不额外计数。
- 卡片/容器：每个背景 `shape` 计 1；容器不会自动包含其子元素。
- 表格：整张表计 1，不把单元格分别计入元素数；但每个单元格仍需通过内容和尺寸检查。
- 图表：整张图计 1，类别、系列和标签不单独计数。
- 图片：每张图片计 1。
- 流程节点：容器和文本分别计 1；连线或箭头每个计 1。
- `rows`、`columns`、`grid`、`card`、`overlay` 等语义节点本身不计数，只有编译结果计数。
- 模板背景、页脚、Logo、右上角装饰由宿主添加，不计入页面内容预算，但单独执行模板叠加和安全区检查。

建议预算：

| 页面类型   | 目标内容元素 | 硬上限 | 说明                      |
| ---------- | -----------: | -----: | ------------------------- |
| 封面       |          5–8 |     10 | 不含模板背景和装饰        |
| 感谢页     |          3–5 |      6 | 不含模板背景和装饰        |
| 目录页     |        10–16 |     18 | 5–6 个目录项              |
| 简单结构页 |         8–12 |     14 | 最多 4 个同构内容块       |
| 复杂结构页 |        16–20 |     24 | 不含宿主背景、页脚和 Logo |

复杂页建议分区：

- 标题区：1–2 个元素。
- 主内容区：10–15 个元素。
- 结论/请示区：1–3 个元素。
- 连接线或强调装饰：0–4 个元素。

超过硬上限时应拆分页面或减少装饰，不应通过叠加 `overlay`/`free` 硬塞内容。

## 4. 详细用例

### COV-01 标准封面

输入：

- 主标题：`集团军用计算业务高质量发展专项论证报告`
- 副标题：`发挥国产网信全链条优势，打造军用计算业务新增长极`
- 汇报单位：`长沙湘计海盾科技有限公司`
- 日期：`2026年10月`

预期：

- 使用模板封面页的外观、背景和装饰。
- 主标题、副标题、单位、日期各出现一次。
- 不出现正文页页脚和右上角正文装饰。
- 不保留模板原文字“关于AI服务器的申购汇报”。
- 恰好 1 页，不追加致谢页。

重点检查：

- 标题是否被重复编译成第二个正文标题。
- 标题和副标题是否重叠。
- 单位、日期是否落在安全区域。

### COV-02 长标题封面

输入：

- 主标题：`面向十五五新域新质作战需求构建自主可控军用智能计算产业新体系`
- 副标题：`以国产芯片、操作系统和整机协同为基础，形成可持续演进的计算能力`
- 日期：`2026年10月`

预期：

- 标题最多两行，不裁切、不压副标题。
- 不通过缩小到不可读字号勉强塞入。
- 与 COV-01 使用相同的模板锚点和视觉层级。

重点检查：

- 自动换行后的真实高度是否参与下一次布局。
- 标题与副标题、日期之间的最小间距。

### THX-01 标准感谢页

输入：

- 主文字：`感谢观看`

预期：

- 使用 `template-page-19` 的结束页设计。
- 只生成 1 页，不再追加 `closing-1.page`。
- 不添加正文背景、正文页脚或无关装饰。
- 主文字清晰、居中，保留模板视觉权重。

### THX-02 模板原生结束语

输入：

- 主文字：`请领导讲话`

预期：

- 同样识别为结束页，复用 `template-page-19`。
- 不出现两个致谢页。
- 文本完整性校验通过。

重点检查：

- 结束页识别不能只依赖“感谢/谢谢”，应覆盖模板页语义和页面角色。

### AGD-01 五章节目录

输入：

1. `军用计算业务发展现状与趋势`
2. `未来军用计算业务发展需求`
3. `集团业务基础与竞争格局`
4. `高质量发展规划与实施路径`
5. `组织、人才与资源保障`

预期：

- 目录编号 01–05 完整且顺序正确。
- 五项使用一致的编号锚点、标题基线和间距。
- 正文使用模板背景与公司页脚。
- 文本框和编号块不得使用相同 bounds。

重点检查：

- 编号、标题、说明文字是否被编译到同一容器区域。
- 目录最末项是否压到公司页脚或右上角装饰。

### AGD-02 六章节长目录

输入：

1. `发展现状、全球趋势与竞争格局研判`
2. `军方装备定制化算力需求与业务空间`
3. `集团自主计算产业链和核心能力`
4. `重点产品、标准体系与生态协同`
5. `十五五阶段实施计划与项目清单`
6. `组织机制、人才队伍和资源保障`

预期：

- 六项全部显示，无截断或重叠。
- 长描述允许两行，但不挤压编号。
- 若纵向空间不足，应降低装饰密度或调整布局，不允许缩小到不可读字号。

重点检查：

- 目录中间项与页脚之间的安全距离。
- 长文本换行后的实际高度。

### SIM-01 三张等宽目标卡

输入：

- 页面标题：`本期交付目标`
- 目标一：`统一接口与数据口径`
- 目标二：`打通需求到发布链路`
- 目标三：`提升性能与稳定性`

预期：

- 三张卡等宽、等间距、同高。
- 每张卡只有一个标题和一个说明文本区域。
- 卡片标题和说明垂直排列，不复用同一 bounds。
- 页面元素总数不超过 14 个可见元素。

### SIM-02 双栏范围对比

输入：

- 页面标题：`本期范围与验收边界`
- 左栏 `本期覆盖`：
    - `核心业务模块与对外适配层`
    - `接口重构与数据口径统一`
    - `发布流程自动化`
- 右栏 `本期不做`：
    - `多租户改造`
    - `历史系统下线`
- 底部结论：`功能验收通过、监控全接入、支持灰度和一键回滚`

预期：

- 双栏边界清晰，左右文本不串栏。
- 即使左右内容行数不同，卡片底部仍对齐。
- 底部结论不压正文卡片或公司页脚。

### CMP-01 KPI + 2×2 矩阵 + 结论

输入：

- 页面标题：`军用计算能力建设路线`
- KPI：
    - `P95 响应下降 30%`
    - `关键链路可用性 ≥ 99.9%`
    - `交付周期缩短约 20%`
- 2×2 矩阵：
    - `统一算力底座`
    - `边缘智能节点`
    - `星载智能处理`
    - `安全可信体系`
- 结论：`以统一底座支撑多场景计算，以模块化产品降低交付成本`

预期：

- KPI 行、矩阵、结论形成三层清晰区域。
- 三个 KPI 等宽对齐，四个矩阵单元格等宽等高。
- 每个单元格标题和说明各自拥有独立 bounds。
- 页面目标为 20 个内容元素：
    - 页面标题 1。
    - KPI 数值 3。
    - KPI 标签 3。
    - 矩阵背景卡 4。
    - 矩阵标题 4。
    - 矩阵说明 4。
    - 底部结论 1。
- 硬上限为 24 个内容元素，不含模板背景、页脚和 Logo。
- 所有元素位于画布和模板安全区内。

该用例用于观察复杂页面的首轮重叠率和修复轮数。

### CMP-02 表格 + 流程 + 请示框

输入：

- 页面标题：`十五五前期重点建设任务`
- 表格：

| 任务           | 关键动作             | 阶段      |
| -------------- | -------------------- | --------- |
| 统一模块化平台 | 完成五类标准模块     | 2026–2027 |
| 典型装备适配   | 地面、舰艇、航空验证 | 2027–2028 |
| 星载智能计算   | 工程样机与在轨验证   | 2028–2030 |

- 流程：`技术验证 → 型号适配 → 规模交付`
- 请示框：`建议批准专项立项，并同步启动跨单位联合攻关`

预期：

- 表格所有单元格文字完整，无横向裁切。
- 流程节点不压表格或请示框。
- 请示框是唯一视觉强调区，不与表格标题冲突。
- 页面目标为 14 个内容元素：
    - 页面标题 1。
    - 表格 1。
    - 流程节点背景 3。
    - 流程节点文字 3。
    - 流程箭头 2。
    - 请示框背景 1。
    - 请示标题 1。
    - 请示正文 1。
- 硬上限为 20 个内容元素，不含模板背景、页脚和 Logo。
- 页面首轮不得出现 `text-overlap`、`text-clipped`、`text-overflow`。

### REG-P02 第 2 页高密度现状与对照回归

来源：用户任务 `889e7f585f5c4242bf2c77c9cb8caf96` 的第 2 页
`pages/02-industry-status.page`。该页首轮出现 9 项机械问题，经过 3 轮修复后仍因第二张
指标卡说明出现孤字“幅”而触发 `PageGateFailed`。

该用例是补充诊断用例，不替代上述 10 个强制用例，也不默认进入全量基准。完整输入保存在
`benchmarks/single-page-template/inputs.v1.json` 的 `REG-P02` 节点，包括原始页面规划、
阅读任务、视觉方案、完整标题、副标题、三条状态栏、核心判断、四张指标卡和四行三列对照表。

输入摘要：

- 页面标题：`算力成为第三大战斗力要素，国内自主可控体系加速成熟`
- 副标题：`全球军事竞争转向决策优势，在轨智能计算迈入实质性验证与初步组网阶段`
- 状态栏：机械化、信息化、智能化三段演进说明。
- 核心判断：平台中心战转向决策中心战，OODA 循环、俄乌/美以伊冲突及国产化率内容完整保留。
- 指标卡：`超300万`、`6.9%`、`1.94万亿元`、`744TOPS` 及各自说明。
- 对照表：代表项目、典型能力、路线与阶段三行，包含国内外完整事实与数字。
- 整稿级要求：完整演示必须在封面后生成独立“目录”页，按顺序列出五个一级章节：
  军用计算业务发展现状与趋势分析、未来军用计算业务发展需求、集团军用计算业务发展基础与现状、
  集团军用计算业务高质量发展规划、全方位保障措施。目录使用模板正文背景和公司页脚。

预期：

- 恰好生成 1 页正文，使用固定模板正文背景、公司页脚和右上角装饰。
- 全部必需文字、数字、百分比、单位、日期和专有名词完整出现。
- 四张指标卡等宽对齐，第二张卡说明保持单行或使用不产生孤字的均衡断行。
- 表格四行完整，不发生 `text-overlap`、`text-clipped`、`text-overflow`，正文不使用不可读字号。
- 首轮 AI 视觉审稿必须 `passed`，不得依赖修复后通过。
- 内容元素为 24 个，硬上限同为 24 个；不含模板背景、页脚和 Logo。
- 首轮目标 110 秒，硬上限 150 秒，进程绝对超时 240 秒。

`REG-P02` 的单页 runner 仍只生成第 2 页，不会因整稿级目录要求输出第二页。目录要求
保存在 `deckRequirements` 中，供整稿规划与后续多页验收使用；标准目录页本身继续由
`AGD-01` 和 `AGD-02` 覆盖。

单独运行：

```bash

```

## 5. 质量门禁

### Q1：模板门禁

- 使用指定模板 `d962...`。
- 封面和感谢页使用对应模板页，不使用正文背景。
- 正文章节使用模板背景、页脚和公司元素。
- 不残留模板原文字。
- 不产生多余页面。

### Q2：结构门禁

- 页面数严格为 1。
- 元素 ID 唯一。
- 元素 bounds 合法且不越界。
- 卡片子元素不得共享同一区域。
- 文本、表格内容完整。

### Q3：浏览器门禁

- `text-overlap = 0`
- `text-clipped = 0`
- `text-overflow = 0`
- `text-contrast = 0`
- 公司页脚和右上角装饰不与正文冲突。

### Q4：AI 视觉门禁

- 视觉模型必须实际读取当前页图片。
- 审稿引用元素必须真实存在。
- 结果必须覆盖当前页。
- 最终状态必须是 `passed`。

### Q5：内容与设计门禁

- 标题只出现一次。
- 正文与测试输入一致，不新增事实。
- 数字、单位、日期和专有名词完整。
- 同类卡片尺寸、间距、字体层级一致。
- 不把单页强行做成多页内容。

## 7. 时间要求

时间统一从“当前页生成请求开始”计时，到对应结果产生为止，不包含模板首次导入和完整演示规划。模板加载、规划、页面生成、编译、浏览器检查、视觉审稿和修复分别记录。

| COV-02 长标题封面         |        70 秒 |         110 秒 |       165 秒 |

| CMP-02 表格、流程与请示框 |       100 秒 |         145 秒 |       210 秒 |

判定规则：

- “目标”按 3 次运行的中位数判定。
- “硬上限”要求 3 次运行全部不超过。
- 基准门禁要求首轮直接通过，不允许把修复后的结果计为性能通过。
- 允许保留 1 轮修复作为诊断信息，但发生修复时本次运行判定为质量回退，不能计入达标结果。
- 绝对超时只用于终止失控任务；达到绝对超时直接判定失败。
- 时间达标不能替代质量门禁；质量和时间必须同时通过。

## 8. 基准测试执行策略

1. 首次实现完成后先跑一次 smoke，只验证链路和产物。
2. 正式基线对每个用例运行 3 次。
3. 每次记录原始结果，不覆盖历史。
4. 报告每个用例的中位数、最大值和异常值。
5. 首轮通过率和平均修复轮数单独统计，不能只用最终通过率掩盖生成质量问题。
6. 修改布局引擎前后使用完全相同的用例、模板、模型和缓存设置对比。

建议输出目录：

## 9. 基线观察指标

除上述绝对时间预算外，每次运行还必须观察：

- 首轮无修复通过率。
- 每页首轮平均问题数。
- 每页平均修复轮数。
- 浏览器检查耗时。
- AI 视觉审稿耗时波动。
- 无效视觉结果数量。
- 单页总耗时。
- 修复带来的额外耗时。
- 编译后元素数量与提示词预算的偏差。

质量优化优先目标：

1. 五类基础用例首轮通过率达到 100%。
2. 复杂结构用例首轮机械问题为 0。
3. 修复轮数从当前多轮降到 0–1 轮。
4. 在不牺牲可读性的前提下减少视觉审稿重试。

## 10. 后续调整要求

- 本文和 `cases.v1.json` 是后续页面生成迭代的强制回归基线，不能用其他临时样例替代。
- 修改布局引擎、页面提示词、模板叠加、渲染、视觉审稿或视觉修复后，必须运行全部 10 个用例。
- `REG-P02` 是第 2 页失败的诊断回归用例；默认可与 10 个强制用例分开运行，只有显式传入
  `--case REG-P02` 时执行。
- 日常开发至少完成每个用例 1 次 smoke；合并或发布前必须完成每个用例 3 次正式运行。
- 任意用例质量失败、超过最终硬时限、或在首轮通过时超过首轮硬时限，均阻止合并。
- 相对上一版基线，单例中位耗时回退超过 10% 时必须解释并提供更新前的对照数据。
- 新增、删除或修改用例与时间预算必须作为独立变更评审，并同步更新本文和 `cases.v1.json`。
