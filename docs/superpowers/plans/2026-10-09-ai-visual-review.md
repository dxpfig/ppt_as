# 全自动视觉审稿实施方案

用户已批准全自动检查、定位、修复和复审，不设置人工审核流程。

## 接入与边界

1. `visual_review.py`：独立视觉模型配置、真实图片能力验证、整稿联系表及全部高清单页审查，严格校验覆盖范围和问题位置。
2. `visual_repair.py`：仅对指定页现有元素进行布局和样式修复；代码层保护正文、数字、公式、图表数据、资源、备注和动画。
3. `visual_pipeline.py`：私有候选稿和渲染产物、最多两轮自动修复、检查点恢复、版本冲突与取消保护。只有通过全部审查才能发布。
4. `pptd_generation.py`：在整稿规划前确认场景，完整注入对应 Kimi 原始规则。
5. 执行状态和前端：显示整稿审查、逐页审查、自动修复、复审结果；仅展示工作摘要，不展示模型内部推理。

## 验证

- 单元与 HTTP 生命周期测试：完整图片输入、漏页、无效响应、内容保护、重试限制、取消、恢复和版本冲突。
- 实际模型图片能力探测；隔离测试稿的真实审查、修复及复审。
- 现有项目回归、前端构建和浏览器交互验证。
- 验证失败保留检查点并如实报告，不绕过视觉门禁，不要求用户承担审稿工作。
