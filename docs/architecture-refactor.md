# 生成架构重构基线

## 决策

保留快速模式和专家模式两个产品入口，但内部采用“一个生成平台 + 两种 Execution Policy”。

两种模式共享：

- 项目、文档 revision 和版本存储
- 上下文、模板、参考资料、知识库和研究服务
- 模型访问、限流、预算和检查点
- 页面状态、渲染、结构校验和导出
- 视觉审稿和修复安全约束

两种模式只在以下方面不同：

- 规划和页面生成方式
- 批次与迭代预算
- 视觉审稿深度
- 自动修复和交付策略

## 当前落地

`agent_service/execution_policy.py` 是第一步，集中读取快速/专家模式的默认参数并做边界校验。

- 快速模式：配置页面并发和最终审稿导出。
- 专家模式：配置批次、Agent 迭代、规划尝试、结构修复和布局修复预算。

后续重构应让 Orchestrator、页面队列和资源池读取同一 Policy 对象，避免各模块直接散读环境变量。

## 目标阶段

1. 统一任务状态机和阶段事件。
2. 页面状态使用 `planned → generated → valid → rendered → reviewed → approved`。
3. 模板、页面渲染和视觉审稿按内容哈希缓存。
4. 生成、审稿和导出使用独立资源池。
5. 页面问题使用稳定指纹和停滞检测。
6. 两模式共享渲染、导出和版本发布路径。

## 不变量

- 任何失败或取消都不能发布未完成产物。
- 文档 revision 冲突必须拒绝覆盖。
- 修复不得改变正文、数据、公式、图表值和来源。
- 最终 PPTX、PDF 和预览必须来自同一 revision。
- 模式差异不能复制渲染、审稿和导出实现。
- 重构每一步必须通过 W08-T0 的快速测试和契约测试。
