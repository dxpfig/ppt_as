# PPT 排版修复快速路径

日期：2026-10-22

本分支解决专家模式下真实浏览器发现问题后、修复 Agent 反复探索但未修改页面的问题。

## 行为

- 浏览器实测到文字溢出时，先执行确定性 autofit，不立即调用修复 Agent。
- 修复 Agent 没有修改任何页面时停止自动修复，不再执行无意义的整稿复检。
- 修复后问题指纹和数量均没有改善时停止下一轮 Agent。
- 页面尝试次数、无修改次数、autofit 次数和问题指纹保存到工作区的
  `.repair-state.json`，恢复任务时继续使用。
- 目标页面源码直接注入修复上下文，并把修复工具限制为 Read、Write、Edit 和
  `kimi_slides`，避免 Grep/Glob/Bash 探索耗尽步骤预算。
- 修复进度按已减少的问题数计算，不按模型调用次数计算。
- HTTP 429/500/502/503/504/529 的重试以公开事件显示。
- 单个任务默认保留 500 条公开执行事件，便于定位多轮修复。
- 页面文件一写入工作区就单独渲染成浏览器 PNG；任务 SSE 会增量返回页面预览。
- 每页渲染完成后立即执行单页结构校验和 AI 视觉检视；页面正文从实际 PPTD
  元素中提取，与预览图同步返回。
- 单页检视有界并发执行，不阻塞后续页面继续创作；页面内容再次修改后只重检
  对应页面。
- 页面 Agent 连续多次只探索、不写文件时自动中止该轮，并切换为仅允许
  Write/Edit 的直接写页模式，避免 19 页任务在模板分析上耗尽步骤预算。
- Write/Edit/Read 会自动把工作区相对路径解析为绝对路径；写入和修改仍被
  限制在任务工作区内，防止路径参数错误造成空转。
- 只有工具返回成功且目标确实是 `deck/pages/*.page` 时才计入已写页；
  工具失败会明确显示失败，不再伪装为“执行完成”。
- 每次 Write/Edit 后立即执行单页 PPTD 结构校验；只有结构合法的页面才计入
  已写页，避免“写成功但 schema 错误”的页面触发下一批重复重写。
- 页面 Write/Edit 只允许当前 `continuation.batchPages` 中的目标文件，不能写
  参考文档、额外页面或 `.keep`。
- 每批请求都直接注入最小合法 PPTD 页面模板，明确禁止 `page:` 外层和
  `type/id/x/y/width/height/text` 这套非 PPTD 字段。
- 页面写页阶段不再暴露 `kimi_slides`：不执行全稿 check、convert 或 screenshot，
  由宿主在每次写入后立即完成校验、渲染和审稿。
- 页面通过结构校验后立即封页，后续 Write 会被拒绝；整批页面全部合法时直接
  结束该轮 Agent，不再额外请求模型总结或美化。
- 页面文件改为工作区内带唯一临时文件的原子写入，避免通用 Write 工具的固定
  缓存、diff 和目录命令开销。
- 页面写入按单页批次执行，提示限制为 6—14 个元素、约 1200 字正文，避免单次
  输出过大导致截断。
- 写后校验同时捕获 YAML 语法错误和 PPTD 结构错误；错误会进入受限重写或明确
  失败，不再逃逸为笼统的“生成过程发生异常”。
- 只有标题和元数据、没有 `elements` 的空壳页不计入完成页，也不会发布空白预览。
- 页内写作 Agent 不再挂载 Read/Bash/Grep/Glob，只使用宿主预先注入的
  `batchPagePlans.sourceEvidence`；每批最多检查一次，不在写页阶段反复截图美化。
- 前端在生成期间提供最新页面大图、已生成页面缩略图、检视状态、问题列表、
  页面正文和原图入口。

## 配置

```dotenv
# 页面修复 Agent 最大步骤数，范围 4–40。
PPT_KIMI_LAYOUT_ITERS=10

# 模型繁忙时的重试间隔，范围 0.5–15 秒。
PPT_LLM_RETRY_DELAY_SECONDS=1.5

# 单个任务保留的公开执行事件数，范围 100–5000。
PPT_EXECUTION_EVENT_LIMIT=500
```
