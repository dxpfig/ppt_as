# pptx-surgical — 就地改一份 pptx，不做整包重写

## 0. 先判路由：轮不轮得到本 skill

桌面端在你动手前已经算过一次「这份 pptx 该怎么改」，结论会直接写在当轮上下文里。没看到
结论时按下表自己判一次：

| 情况 | 走哪条 |
|---|---|
| 上下文说**有对齐的 deck 工作副本**（给了 `working files/decks/<名字>-<hash>` 目录） | 改那个目录里的 PPTD，**不要碰 .pptx**，也不要用本 skill |
| 上下文说**没有对齐的 PPTD**，或你在 `working files/decks` 下找不到同名工作副本 | **本 skill** |
| 用户要**新建** deck / 把文档做成 PPT | `kimi-slides`，产物是 `.pptd` |
| 上下文里是一份 `.pptd` | 直接改那份 pptd（`kimi-slides` 的管线），本 skill 不适用 |

**永远不要为了改一份 pptx 去 `kimi-slides convert`。** 那会另生一份 deck 副本：用户预览里
那份 `.pptx` 一个字没动（等于没改），而且 PPTD 是简化模型，装不下加载项私有数据
（think-cell 这类）、内嵌工作簿、内嵌字体——真实文件实测往返一次 433 个部件只剩 201 个，
**不报错**，产物照样能打开，只是图表变成再也编辑不了的死图形、字体掉回系统默认。
转换只由用户在界面上点「编辑」并确认发起。

## 1. 三步闭环

脚本一律用绝对路径调（你的 cwd 不是 skill 目录），路径含空格必须加引号。
脚本只依赖 Python 3 标准库。下面写的 `python3` 若不在 PATH 上（Windows 打包环境只带
`uv`），把每处 `python3` 换成 `uv run --no-project python`（uv 会用内置 Python）。

```bash
SKILL="<skill 根>/pptx-surgical/scripts"

# ① 看清楚：页面清单 + 每段文字的稳定地址 + 这份文件里有什么碰不得
python3 "$SKILL/prep.py" "报告.pptx"
python3 "$SKILL/prep.py" "报告.pptx" --slide 4          # 只看某页

# ② 落刀：ops 里点名要改哪几段（ops 文件名随目标走；备份由 edit.py 自动留，不用手动 cp）
cat > ".报告.pptx.ops.json" <<'JSON'
[
  {"id": "s4#p0", "text": "架构拆解：KDA 与注意力残差"},
  {"slide": 4, "find": "百万上下文", "replace": "长上下文"}
]
JSON
python3 "$SKILL/edit.py" "报告.pptx" --ops ".报告.pptx.ops.json" --dry-run   # 先空跑看清楚
python3 "$SKILL/edit.py" "报告.pptx" --ops ".报告.pptx.ops.json"

# ③ 核对：结构没坏、只有该变的页变了（--before 用 edit.py 自动留的那份）
python3 "$SKILL/verify.py" --self "报告.pptx"
python3 "$SKILL/verify.py" --before ".报告.pptx.before.pptx" --after "报告.pptx"
```

`edit.py` 自带三样保护，遇到它们报错是**预期行为**，按提示来、不要绕过：

- **文件锁**：另一任务正在改**同一份**文件时，报「请等它完成后重试」。等十几秒重跑；
  仍不行就停下告知用户——有并发编辑在进行，不要硬改。
- **自动备份**：就地编辑前自动在同目录留 `.<文件名>.before.pptx`（恒定一份，下次编辑覆盖）。
  核对**通过**后可删掉它与 ops 文件；核对**失败**时留着它——那是恢复原件的唯一依据。
- **写盘前复检**：编辑期间文件被别的程序改动（典型：用户在 PowerPoint 里保存了）会放弃
  写盘，原文件保持对方的新内容——基于现状重新跑一遍即可。

两条使用约束：

- **改前请用户关闭 PowerPoint/WPS 里打开的这份文件**（macOS 上对方保存会覆盖回来；
  Windows 上会直接写盘失败）。
- 含大嵌入媒体的 deck 编辑与核对会变慢、内存冲高，属预期——**不要并发改多个大 deck**，
  中途也不要杀进程（会留 `tmp*.pptx` 残骸，确认没有进行中的编辑后可删）。deck 在
  iCloud/OneDrive 同步目录里时，核对完及时删备份，免得它被上传。

## 2. 两种 op，够用且只有这两种

| 写法 | 语义 |
|---|---|
| `{"id": "s4#p0", "text": "新文字"}` | 把这一整段换成新文字。`id` 来自 `prep.py`，最精确 |
| `{"slide": 4, "find": "旧", "replace": "新"}` | 在该页所有段落里做子串替换。**一段都没命中就报错退出**，不会假装改过 |

一次 ops 可以混用、可以跨页；同一页的多处改动会合并成一次重写。

**带软换行的段落（`prep.py` 标 `{2 行}`、文字里显示 `⏎`）**：段落文本用 `\n` 表示那次
换行，新文本必须给出**同样的行数**（`"上半句\n下半句"`）。行数不一致直接报错退出——
多给了没地方放（本 skill 不新增 `a:br`），少给了会留下渲染成空行的孤立换行符。
要增删换行请让用户走编辑器。

## 3. 保证与代价（说清楚，别指望它做没答应的事）

**保证**

- 没被点名的部件（`ppt/tags/`、`ppt/embeddings/`、`ppt/webextensions/`、`ppt/fonts/`、
  `ppt/media/`、母版与版式…）在新包里**与原包字节一致**——重打包时逐条克隆 `ZipInfo`，
  压缩方式与时间戳都不动。
- 只重写你点名的那几页的 slide 部件。**别的页在审阅面板里不会变成待审**——整包重写
  会让每一页都出一张待审卡，用户得逐页确认一遍。
- 页号（`--slide N`、`sN#pM`、`{"slide": N}`）永远是**放映顺序**（`p:sldIdLst` 的第 N 条），
  不是 `slideN.xml` 里的数字——用户拖过页序或删过页后两者不同。页列表读不出时脚本拒绝改写。
- 写盘前自检：改过的 XML 必须能解析、部件类别不许减少、页数不许变、**重新读一遍产出的包
  逐 op 复核目标段落真的变成了预期文字**；任一条不过就不写盘，原文件保持原样。
- `verify.py --self` 另外校验 OPC 包一致性：每个部件都有内容类型、内部关系不断链、
  `p:sldIdLst` 与真实 slide 部件一一对上（少一条就是那一页不显示）。

**代价（有意的取舍）**

- 一段里原本有多种格式（半句粗体）时，新文字整体继承**该段第一个 run** 的格式。要保住
  段内分段格式就分别改每个 run 所在的段落地址。
- 只改**文字**。加页 / 删页 / 挪版面 / 换图不在本 skill 范围——那些请让用户走「编辑」
  转成 PPTD 之后在编辑器里做（那条路是他明确同意过损耗的）。
- 不依赖 `python-pptx`：那一层保存时会重新序列化整个包，未建模部件能不能活下来取决于它的
  实现，与本 skill 「除了点名的几个字，一个字节都不动」的承诺相冲突。**别改用它。**

## 4. 交付

改完在回答里用产物 marker 把文件交出去，一行：

```
<<daimon-artifact path="/绝对/路径/deck_v2.pptx" title="改好的方案" />
```

客户端会渲染成**可点击链接 + 预览卡**，点一下在预览区打开。

⚠️ **`path` 必须是绝对路径。** 写裸文件名或相对路径时，客户端按**会话工作区根目录**解析；
文件不在那个根下就解析不到 —— 表现是**链接点了没反应**，而链接本身看着完全正常（蓝的、
可点的），最难自查。脚本的输出参数常是相对 cwd 的，交付前先取绝对路径
（`python3 -c "import os;print(os.path.abspath('out.pptx'))"`）。

不要贴 XML 片段，也不要把 ops JSON 这类过程文件写进正文。
